## Один открытый вопрос — с него начинать

**Срезать ли `SHADOWLINK_STAGGER_OFFSET_CAP` 15s → 10s?**

Решение отложено сознательно: пользователь потребовал независимой проверки
Fable-агентом, а тот **трижды подряд упал на API 529 Overloaded** (серверная
перегрузка, к заданию отношения не имеет). Правка тайминга без проверки
запрещена hard rule 8.

Готовое задание для агента — в истории сессии; суть: перепроверить
реконструкцию, оценить цену в conn/час (P0), риск синхронизации ротаций,
влияние на `worstCaseTeardown` и троттлинг гейтов, и честно взвесить вариант
«ничего не делать».

### Что уже установлено по этому вопросу (проверено дважды)

Реконструкция времён жизни 622 ротаций из `nixavpn-DEBUG-20260813-153638.log`
перепроверена строгим методом: **0 разорванных пар, 0 осиротевших стартов**,
все 628 ячеек `gen=1`. Цифры устояли.

```
p50=75.2s  p75=80.2s  p90=80.2s  max=100.2s
>=70s: 594 (95%)   >=80s: 190 (31%)

гистограмма (5s):
  60-65s   10
  70-75s   92
  75-80s  312   ← основная масса
  80-85s  166   ← 87% всех заходов в зону риска
  85-90s    9
  90-95s   12
  95s+      3
```

Ступенчатость — прямое доказательство механизма `base + stagger`: не плавное
распределение, а кластеры по ячейкам лестницы (`STEP=1s`, `CAP=15s`, base 70s
→ реальный порог 70–85s).

**Склоняюсь к «не трогать».** В полосе 80–85s сидят 166 слотов, но за 2 часа
там зарезано ~4 — hazard ниже, чем 3.9% из замера. Правка убрала бы заходы в
полосу, где резов почти нет, ценой роста conn/час (P0 policing по числу TLS).
Но это оценка, а не вердикт: решает проверка.

## Известные незакрытые вещи

1. **Адаптер молчит** (`samples=4 required=12`, `adapt_changes=0`).
   `MinSamplesForInference=12` (`client/slotobs/infer.go:126`) недостижим,
   пока порог работает хорошо: резов 1.96/час. Порочный контур — успех
   подавляет доказательства собственной правоты. Правкой порога НЕ лечится.
   Развязка: считать по hazard-кривой со знаменателем из плановых ротаций
   (`RecordPlanned`, знаменатель не цензурирован). Отдельная работа со своим
   замером — сознательно не отдана агенту вместе с остальным.
2. **`worstCaseTeardown()` завышен** — 142.5s против наблюдаемого max 104.7s
   (при 150s). Слагаемые `stagger 48s` и `deferred 30s` в поле не наблюдались.
   Чинить осторожно: занижение хуже завышения.
3. **Гейт `observed_age_p90`** сравнивает worst-case с величиной, приколотой
   к нашему же `MAX_SLOT_AGE`. Fable отказался чинить обоснованно: подмена на
   величину из резов вернула бы survivorship bias. Добавлено поле
   `observed_p90_capped_by`, чтобы ограничение было видно.
4. **Push не делался** ни разу — 4 коммита ждут решения пользователя.
