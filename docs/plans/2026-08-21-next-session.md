## Что проверять в следующем прогоне

```bash
LOG="$TEMP/nixavpn-DEBUG-<дата>.log"

# 1. ГЛАВНОЕ: резы в дренаже должны уйти. Смотреть last_write_age_ms, а не cause.
grep 'slot reader error' "$LOG" | grep close_other \
| sed -n 's/.*slot=\([0-9]*\).*slot_age_ms=\([0-9]*\).*last_write_age_ms=\([0-9]*\).*/slot=\1 age=\2 lastw=\3/p'
#    Резы считать ТОЛЬКО так (grep close_other), а не глазами по кластерам:
#    первым проходом 08-20 я насчитал 4 из 5, потеряв 12:17:51.

# 2. НОВОЕ: разнос keepalive теперь наблюдаем. spread_ms — факт, не константа.
grep 'keepalive sent' "$LOG" | grep -o 'spread_ms=[0-9]*' | cut -d= -f2 \
| sort -n | awk '{a[NR]=$1} END{print "p50="a[int(NR/2)], "p99="a[int(NR*0.99)], "max="a[NR]}'
#    Ожидается max <= ~400 (spread_cap_ms). Сумма вместо максимума = кумулятивность.

# 3. Цена правки: лишние кадры к origin. Дренаж = 0.79% слото-времени
#    (2053 с из 259 991 = (прогон − зависания) × 8; +39 кадров/ч из 5760), поэтому
#    рост encrypts должен быть в пределах шума.
grep 'stats (delta)' "$LOG" | grep -o 'encrypts=[0-9]*' | cut -d= -f2 \
| sort -n | awk '{a[NR]=$1} END{print "p50="a[int(NR/2)], "p90="a[int(NR*0.9)]}'
```

⚠ **Сначала проверить, не спал ли ноут** — иначе все числа врут в разы:

```bash
# дыры > 60 с. Сон = дыра без флеша; возрасты слотов = длительности дыры.
sed -n 's/^time=[0-9-]*T\([0-9][0-9]\):\([0-9][0-9]\):\([0-9.]*\).*/\1 \2 \3/p' "$LOG" \
| awk '{t=$1*3600+$2*60+$3; if(p&&t-p>60) printf "дыра %.1f мин\n", (t-p)/60; p=t}'
```

Прогон 08-20 дал дыры 58.7 мин (сон) и 36.9 мин (закрытие ноута). Последствия:
`age_exposure_over_threshold_ms` показал 28 989 с при реальных **1 120 с** —
накопление идёт по КАЖДОМУ слоту, то есть poolSize × длительность сна (8 × 3484 с
≈ 27 869 с, ровно наблюдённый прирост). Туда же 8 «резов» одним кластером в
22:11:27 и WARN про бюджет ротации с `observed_age_p90 = 59m46s`. Брать последнюю
health-строку ПЕРЕД дырой; кластер на пробуждении исключать из hazard и из резов.
Сторож бюджета сработал корректно — чинить его не надо.
